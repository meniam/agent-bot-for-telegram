# Правила подключаются из корневого `AGENTS.md` папки с проектами, копия удалена

Decided: 2026-09-06
Plan: —
Revised: —

## Context

С 2026-09-06 12:47 правила лежали копией в `.agents/rules/`
([решение](20260906_1247_journals_follow_shared_rules.md)): довод — репозиторий клонируется на сервер, где
домашнего каталога нет. На 2026-09-06 копия уже разошлась с источником:
в копии отсутствовали `justfile.md`, `python.md`, `ruff.md`, а индекс `AGENTS.md` был отредактирован под проект. Евгений решил: правила подключаются один раз в корневом `AGENTS.md`
папки с проектами (`www/AGENTS.md`), а проекты на его личный каталог не ссылаются и копий не держат.

## Decision

- Каталог `.agents/rules/` удалён из репозитория.
- Правила журналов и `db.md` подключает корневой `AGENTS.md` папки с проектами (`www/AGENTS.md`).
  Корневой `AGENTS.md` проекта и `AGENTS.md` каталогов журналов их не
  подключают и на `~/.agents/rules` не ссылаются — называют правило только по
  имени файла.
- Всё остальное из прежнего решения в силе: четыре журнала, формат записей,
  замороженные старые записи.

## Why

- Правила — личные предпочтения Евгения, а не свойство проекта: проект не
  должен знать, где они лежат. Одна точка подключения на все проекты.
- Копия требует ручной синхронизации и уже отстала: одно правило в трёх
  редакциях по проектам хуже, чем одно правило в одном месте.
- Отвергнута прямая ссылка `@~/.agents/rules/…` из проекта: сделана и убрана
  в тот же день — проект ссылался бы на личный каталог.
- Отвергнут симлинк на `~/.agents/rules`: он попал бы в git и висел бы
  битым на сервере.

## Cost

- Вне папки с проектами (клон на сервер, другая машина) агент правил журналов
  не увидит: они приходят только через родительский `AGENTS.md`. Условие
  пересмотра — агент, работающий с репозиторием вне этой папки.
- Ссылки на `.agents/rules/…` в старых записях журналов остаются как есть:
  записи не переписываются, читающий знает, что каталог удалён 2026-09-06.
