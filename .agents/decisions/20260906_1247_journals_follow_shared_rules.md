# Журналы ведутся по общим правилам из `.agents/rules`

Plan: —
Revised: revised by [Старые планы переименованы в схему `YYYYMMDD_HHMM_name`](20260906_1310_old_plans_renamed_to_timestamp_scheme.md) 2026-09-06; revised by [Правила подключаются из корневого `AGENTS.md` папки с проектами, копия удалена](20260906_1848_rules_included_from_cluster_copy_removed.md) 2026-09-06

## Context

Планы лежали в `docs/plans/PLN-0001`–`PLN-0007` и были исключены из git
(`docs/plans/` в `.gitignore`); решения и найденные факты жили внутри планов
в таблицах «Decision log» и разделах «Known facts», changelog не вёлся.
Общие правила журналов есть в `~/.agents/rules` и уже применены в
`brain-agent`: файл на запись, `_TOC.md`, имена `YYYYMMDD_HHMM_statement.md`.

## Decision

- Правила лежат копией в `.agents/rules/` (`AGENTS.md`, `db.md`, `plans.md`,
  `decisions.md`, `learning.md`, `changelog.md`). Источник — `~/.agents/rules`,
  обновление — копированием руками. `python.md` и `ruff.md` не копируются:
  они применяются через `pyproject.toml` и `justfile`, а не читаются агентом
  в каждой сессии; в копии индекса `AGENTS.md` их строки убраны.
- Четыре журнала: `.agents/plans/`, `.agents/decisions/`, `.agents/learnings/`
  и `CHANGELOG.md` в корне. У каждого каталога свои `AGENTS.md` и `CLAUDE.md`,
  которые подключают соответствующее правило через `@../rules/<file>.md`.
  Корневой `AGENTS.md` подключает `decisions.md`, `learning.md`, `changelog.md`.
- Планы `PLN-0001`–`PLN-0007` переезжают в `.agents/plans/` как есть, без
  переименования, и с этого момента коммитятся; `docs/plans/` из `.gitignore`
  убран. Новые планы получают имя по правилам. *(Пункт про имена пересмотрен
  в тот же день, см. `Revised`.)*
- Старые решения и факты из планов не переносятся. Пересмотр — новый файл
  со ссылкой на план.
- Ключи заголовков и названия разделов записей — английские, как в правилах;
  текст — по-русски. Код и докстринги остаются на английском.

## Why

- Копии, а не симлинки на `~/.agents/rules`: репозиторий разворачивается в
  Docker-образ и клонируется на сервер, где домашнего каталога нет.
- Планы попадают в git: план по правилам — способ передать задачу другому
  агенту, а невидимый в репозитории план этого не делает. Старые планы
  сохраняют имена, чтобы не переписывать историю.
- Отвергнуто «оставить планы в `docs/plans/`»: два места для планов и
  правило, которое не является общим.
- Отвергнуто «перенести старые decision log в файлы»: переписывание задним
  числом, которое правила запрещают.

## Cost

- Правила обновляются вручную: изменение в `~/.agents/rules` не доезжает
  само, пока его не скопируют.
- В контекст каждой сессии добавляются правила трёх журналов из корневого
  `AGENTS.md` (около 14 КБ).
- Старые решения ищутся по планам, новые — по `_TOC.md`.
