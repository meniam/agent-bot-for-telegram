# Database Rules

PostgreSQL. Applies to migrations, SQL, ORM models, fixtures, docs.
Naming only; data modeling is separate.

## General

- English, lowercase `snake_case`, `^[a-z][a-z0-9_]*$`.
- No quoting. No `CamelCase`, hyphens, double or trailing `_`.
- No reserved words or type names: `user`, `order`, `group`, `text`, `date`.
- No `pg_` prefix.
- No object-type prefixes: `person`, not `tbl_person`; `name`, not `col_name`.
- One concept, one word. Never mix `user` / `account` / `member`.
- Only common abbreviations: `id`, `api`, `ip`, `url`, `sku`.
- Name limit 55 chars (PostgreSQL truncates at 63; keep headroom).
- DB names are canonical. camelCase in code is mapped on the code side.

## Namespaces

**Schema** = ownership boundary, not grouping.

- Domain model lives in `public`. Extensions are installed in `public` too.
- SQL always schema-qualifies names: `public.session`.
- New schema only when owner/roles, permissions, retention differ,
  or it is a third-party component.
- No schema per code module; that is a prefix.
- Schema is not repeated in the name: `audit.event`, not `audit.audit_event`.
- App role gets `usage`, migration role gets `create`. `create` on `public` is revoked.

**Table prefix** = namespace inside a schema. Answers "why does this exist"
or "who owns the rows".

- Integration/channel: `telegram_user`, `notion_page`, `stripe_event`.
- External ids live in the integration table, not the domain table:
  `telegram_user.telegram_user_id`, FK `telegram_user.person_id → person.id`.
- New integration = new prefix, not new columns in a domain table.
- Synced reference data: `lib_country`, `lib_currency`. Written only by sync,
  rows never deleted. Own reference data has no prefix.
- No other prefixes.

## Tables

- Singular noun: `person`, `order_line`.
- Relation/collective: uncountable singular: `workspace_access`, `usage_log`.
- Reserved word → nearest domain term: `purchase_order`, `person`.
- App account is `user_auth`: login, password, roles.
  Not `user`, `users`, `app_user`. Human profile is separate: `person`.
  FK to account: `user_auth_id`.
- Banned: `data`, `items`, `records`, `mapping`, `details`, `info`, `misc`.
- Relation that is a concept gets a domain name: `workspace_access`.
  Mechanical join table: `<a>_<b>` alphabetical: `product_tag`.
- Append-only journal: `_log`, no `updated_at`. Row versions: `_history`.
  Domain events: `_event`.
- Translations: `<entity>_translation` table, not `name_ru` / `name_en` columns.
- Test: "one row is a …" must complete unambiguously.

## Columns

**Keys**

- PK is `id`, type `uuid`. Generated by the app, no DB default. No `serial`.
- FK is `<role>_id`: `person_id`. Multiple refs to one table need a role:
  `owner_person_id`, `actor_person_id`.
- External id: `external_id` + `provider`, or `telegram_user_id` when provider is fixed.
- Composite PK only on join tables and integration reference data.

**Types**

- Strings: always `text`. Length via `check (length(x) <= n)`, never `varchar(n)`.
- Nullable by default. `not null` only where the model requires it.
- Integers: `integer` by default, `bigint` for ids, counters, money. No `smallint`.
- Money: `numeric(14, 2)` or integer minor units. Precision always explicit. No `float`.
- JSON: always `jsonb`, never `json`. Filtered fields go to columns, not into `jsonb`.
- Collections: join table by default. Array only as an explicit decision.
- Email/login: stored lowercase, normalized by the app. No `citext`.

**Values**

- Table name not repeated in columns: `person.first_name`.
- Scalar singular, array plural: `tag` / `tags`.
- Point in time: `_at`, `timestamp` without zone: `created_at`.
  `timestamptz` is not used.
- One timezone per project, default `Europe/Moscow`. Set at DB level:
  `alter database <db> set timezone = 'Europe/Moscow'`. App never overrides
  session timezone. Then `default now()` writes project time.
- Date: `_on`, `date`: `starts_on`.
- Period: `starts_at` / `ends_at`. `valid_from` / `valid_to` allowed when
  the meaning is validity, not an event span.
- Countable: `_count`: `product_count`, `user_count`, `retry_count`.
- Unit in name: `duration_sec`, `duration_ms`, `size_bytes`, `price_cents`. Money column has a `currency` next to it.
- Boolean: positive predicate, no `is_`/`has_`: `enabled`, `verified`.
  Not `disabled`, not `not_deleted`. `not null` by default; nullable only
  with a reason.
- Identifiers: `slug` for URL, `code` for a stable machine id. `key` is not used.
- Sort order: `pos`, not `order` / `sort` / `weight` / `position`.
- Denormalized / cached columns: per-project decision.
- Full-text: `search_tsvector`, `generated always as (...) stored`, `gin` index.
- Type not encoded: `metadata`, not `metadata_jsonb`.
- Entity label is `name`, not `title`. External `title` is renamed by the adapter.
- Field group of one subject shares a prefix: `company_position`,
  `company_manager_person_id`. Role on FK is kept.
- Enum: `text` + `check`. PostgreSQL `enum` is not used.
- Soft delete: `deleted_at timestamp`, not `deleted boolean`.

**Standard columns** of a domain table:

```sql
id          uuid        not null,
created_at  timestamp   not null default now(),
updated_at  timestamp   not null default now()
```

`updated_at` is set by trigger or ORM. Join tables and logs have no `updated_at`.

**Column order** in `create table`. Physical order is permanent; `add column`
always appends.

1. `id`
2. Tenant / owner FK
3. Other FKs
4. Domain values: text, numbers, domain dates (`ships_on`)
5. Flags with their paired timestamps: `paid`, `paid_at`
6. `jsonb` / `metadata`
7. `created_at`, `updated_at`, `deleted_at`

- Actor columns follow their timestamp: `created_at`, `created_by_user_auth_id`.
- Join table: PK columns first, in PK order.
- Flag + timestamp pair kept consistent: `check (paid = (paid_at is not null))`.
- Alignment padding is ignored, except: do not interleave `boolean` and 8-byte types.
- Constraints after columns: PK → FK → unique → check.
- Indexes as separate `create index`: composite → FK coverage → partial.

## Constraints and Indexes

Names always explicit. Auto-generated names are rejected.

| Object    | Pattern                            | Example                              |
| --------- | ---------------------------------- | ------------------------------------ |
| PK        | `<table>_pk`                       | `person_pk`                          |
| FK        | `<table>_<columns>_fk`             | `session_person_id_fk`               |
| Unique    | `<table>_<columns>_uidx`           | `chat_bot_id_chat_id_uidx`           |
| Check     | `<table>_<rule>_chck`              | `person_status_allowed_chck`         |
| Exclusion | `<table>_<purpose>_excl`           | `reservation_no_overlap_excl`        |
| Index     | `<table>_<columns_or_purpose>_idx` | `session_person_id_last_used_at_idx` |
| Trigger   | `<table>_<purpose>_trg`            | `person_set_updated_at_trg`          |
| Function  | `<verb>_<object>`                  | `set_updated_at`                     |
| View      | `<noun>`                           | `usage_request_cost`                 |
| Mat. view | `<noun>_mv`                        | `daily_usage_mv`                     |
| Sequence  | `<table>_<column>_seq`             | `invoice_number_seq`                 |

- Columns in definition order. No `_and_`. No schema in the name.
- Partial/expression index named by purpose: `session_active_for_cleanup_idx`.
- No duplicate indexes on PK/unique. `not null` is not named.
- Every FK is covered by an index.
- `on delete` always explicit: `cascade` / `restrict` / `set null`.
- `on update` is a per-project decision, not fixed here.
- Functions and triggers: `set search_path` inside a function is forbidden;
  names are schema-qualified instead.
- Views: `security_invoker`. Updatable views are not used.

## Composite Index

Index works left to right: `(a, b, c)` serves `a`, `a+b`, `a+b+c`,
but not `b` or `c` alone.

**Name**

- Pattern: `<table>_<col1>_<col2>_..._idx`, columns in definition order.
- Sort direction not in name: `(person_id, created_at desc)` →
  `session_person_id_created_at_idx`.
- Composite unique: `_uidx`: `workspace_slug_uidx` for `(workspace_id, slug)`.
- `include` not in name: `session_person_id_created_at_idx`
  even with `include (name)`.
- Partial index named by purpose, not by columns and condition:
  `session_active_idx`, not `session_person_id_created_at_archived_at_null_idx`.
- Expression index named by meaning: `person_email_lower_idx`
  for `(lower(email))`.
- `_id` suffix is kept: `person_id`, not `person`.
  Otherwise `session_person_idx` reads as an index on a nonexistent column.
- Over 55 chars: replace column list with purpose:
  `telegram_message_chat_topic_lookup_idx` instead of
  `telegram_message_telegram_chat_id_telegram_topic_id_created_at_idx`.
  List columns in the index comment.

```sql
create index session_person_id_status_created_at_idx
  on public.session (person_id, status, created_at desc);

create index session_active_idx
  on public.session (person_id, created_at desc)
  where archived_at is null;

create unique index workspace_slug_uidx
  on public.workspace (workspace_id, slug);
```

**Key column order**

1. Equality (`=`, `in`) first.
2. Range (`>`, `<`, `between`, `like 'x%'`) after equality. Anything right
   of a range no longer filters.
3. Sort (`order by`) last, same direction as the query.
4. Equal role: more selective column goes left.

Example above: `where person_id = ? and status = ? and created_at > ?
order by created_at desc` → `(person_id, status, created_at desc)`.

**Composite vs separate**

- Columns filtered together in one query → composite.
- Columns filtered independently in different queries → separate.
- One composite beats several singles: PostgreSQL can bitmap-and,
  but composite is cheaper and provides sort.

**Redundancy**

- `(a, b)` covers `(a)`. No separate index on `a`.
- `(a, b)` does not cover `(b)` or `(b, a)`.
- FK column counts as covered when first in a composite index.
- Before adding an index, check `pg_indexes` for one with the same prefix.

**Covering index**

- Columns only read, not filtered, go to `include`, not the key:
  `(person_id, created_at) include (name)`. Enables index-only scan.
- No wide columns in `include` (long `text`, `jsonb`).

**Uniqueness**

- Composite unique ordered general → specific: `(workspace_id, slug)`,
  not `(slug, workspace_id)`. First column then doubles as FK index.
- `null` in unique is not a duplicate. If needed: `nulls not distinct`
  (PostgreSQL 15+) or partial unique.

**Partial**

- Index on a row subset: `where` in definition:
  `(person_id, created_at) where archived_at is null`.
- Name by purpose, not expression: `session_active_idx`.
- Query condition must match index condition or the planner skips it.

**Limits**

- Max 4–5 columns. More is a signal to revisit the query or model.
- Every index slows writes. No index without a query behind it.
- Verify with `explain (analyze, buffers)` on real data volume, not an empty table.

## Migrations

- Schema changes only via migration. No `create table` in app code.
- Idempotent when the object may already exist: `if not exists`.
- One migration, one change. File name: timestamp + change:
  `20260902_1430_person_email_unique`.
- `down` is written when rollback loses no data. Otherwise a comment saying why not.
- No data edits, except backfill required by a new constraint.
- Every migration sets `lock_timeout` and `statement_timeout`.
- `create index concurrently` on a live DB, outside a transaction.
- Adding `not null` to an existing column: three steps: nullable column →
  backfill → `check (x is not null) not valid`, `validate`, then `set not null`.
- Column rename/drop takes two deploys: new column + dual write, then drop.
- `alter column type` on a large table only with a written plan.
- One service, one database. Cross-service references are plain ids, no FK.

## Example

```sql
create table public.session (
  id            uuid        not null,
  person_id     uuid        not null,
  name          text        not null,
  archived_at   timestamp,
  created_at    timestamp   not null default now(),
  updated_at    timestamp   not null default now(),
  constraint session_pk primary key (id),
  constraint session_person_id_fk
    foreign key (person_id) references public.person (id) on delete cascade
);

create index session_person_id_created_at_idx
  on public.session (person_id, created_at desc);
```

## Checklist

1. snake_case, no quoting, no reserved words.
2. Table is singular; one row is clearly one thing.
3. One concept, one word.
4. FK, time, counter, unit visible from the name.
5. Schema only as ownership boundary; grouping by prefix.
6. Constraints and indexes named explicitly, ≤ 55 chars.
